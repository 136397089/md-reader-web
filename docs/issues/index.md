## 推进建议

**首批落地（3 个，最高性价比）：**

1. **001 全文搜索** — 阅读类工具第一缺失功能（🔴 注意：必须配套"上限+去抖+超时"，否则拖垮服务端）
2. **002 文档大纲** — 长文导航刚需，纯前端，零后端成本
3. **003 阅读位置记忆** — 纯前端，零后端改动

三者都聚焦核心「阅读」场景。002/003 资源风险低（🟡/🟢），可快速交付；001 价值最高但资源风险最高（🔴），实现时务必先落地防护三件套。

**资源视角的额外建议：**
- **011 阶段一**（密码环境变量化）资源成本极低且修复真实安全漏洞，可随时插入，不与其他需求冲突。
- **008 编辑器**虽体验价值高，但首屏资源风险最高（🔴），建议最后做且严格懒加载。

## 依赖关系

- **010**（高级搜索）依赖 **001**（全文搜索）先行
- **008**（富文本编辑器）建议在 001–007 落地后再做，避免重构耦合
- **011** 阶段一（密码环境变量化）可独立先行

## 资源需求与体验影响总览

> Web 程序的资源约束与桌面程序本质不同：服务端是 **Werkzeug 开发服务器 + 单进程多线程**（CPU 密集请求会阻塞全站）、Markdown 在**服务端同步渲染且无缓存**、首屏依赖 **CDN（MathJax）**、图片**逐张独立请求**、前端状态走 **localStorage**。下表从这些维度评估每个需求。

### 资源风险等级图例
- 🟢 **轻量**：几乎无额外资源开销
- 🟡 **中等**：需配套优化（去抖/上限/节流）才不伤体验
- 🔴 **重资源**：直接影响服务端稳定性或首屏，必须重点防护

| 编号 | 需求 | 服务端负担 | 客户端负担 | 体验影响 | 关键资源风险 / 必做防护 |
|---|---|---|---|---|---|
| 001 | 全文搜索 | 🔴 重 | 🟡 中 | ⭐⭐⭐ 质变 | 全量扫描阻塞线程；**必做：结果上限+去抖+超时** |
| 002 | 文档大纲 | 🟢 零 | 🟡 中 | ⭐⭐⭐ 正向 | scroll spy 重排；**必做：IntersectionObserver/rAF 节流** |
| 003 | 阅读位置记忆 | 🟢 零 | 🟢 轻 | ⭐⭐⭐ 正向 | 异步渲染致位置错位；**必做：晚于 MathJax/图片恢复滚动 + debounce 写入** |
| 004 | 文件收藏 | 🟢 零 | 🟢 轻 | ⭐⭐ 正向 | localStorage 配额共享；**必做：统一命名空间 + 失效文件处理** |
| 005 | 最近打开 | 🟢 零 | 🟢 轻 | ⭐⭐ 正向 | 相对时间勿挂全局定时器 |
| 006 | 图片灯箱 | 🟢 零 | 🟡 中 | ⭐⭐⭐ 正向 | 多图缓存撑爆内存；**必做：仅预加载 ±1 张 + 纯手写免 CDN** |
| 007 | 导出 PDF | 🟢 零 | 🟢 轻 | ⭐⭐ 正向 | **用 `window.print()`，禁引服务端 PDF 依赖** |
| 008 | 富文本编辑器 | 🟢 零 | 🔴 重 | ⭐⭐ 编辑正向 / 首屏负向 | 包体积拖垮首屏；**硬性：懒加载 + 本地化打包，禁进首屏/禁 CDN** |
| 009 | 文档元信息 | 🟢 极低 | 🟢 轻 | ⭐ 正向 | 字数统计服务端一次完成 |
| 010 | 高级搜索 | 🔴 重 | 🟡 中 | ⭐⭐ 进阶正向 | 正则 **ReDoS** 可卡死线程；**必做：超时 + 复杂度限制** |
| 011 | 安全演进 | 🟢 极低 | 🟢 轻 | 安全必选 | 修复明文密码漏洞；阶段一独立先行 |

### 横向资源约束（实现时全局遵守）
1. **服务端是单进程多线程**：任何 CPU/IO 密集接口（001/010）必须自带超时 + 上限，否则一个慢请求拖垮全站。
2. **首屏已被 CDN 阻塞**：新增大型前端依赖（008 编辑器）必须懒加载 + 本地化，禁止进首屏 bundle、禁止新增 CDN。
3. **localStorage 全局共享配额**：003/004/005/010 共用 `mr:*` 命名空间，单项设上限，写操作 debounce，捕获 `QuotaExceededError`。
4. **文档异步渲染时序**：图片加载、MathJax `typesetPromise` 会改变文档高度；凡依赖"渲染完成后"的动作（002 scroll spy、003 滚动恢复、006 翻图、007 打印）必须挂在统一的 `onDocumentRendered(container)` 钩子上，按序执行。
5. **图片逐张请求**：文档多图本就并发挤占线程，新功能（006）复用现有 `/api/image` 缓存，不新增请求放大。

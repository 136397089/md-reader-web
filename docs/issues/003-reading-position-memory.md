## 背景与痛点

每次打开文件都回到顶部，长文读到哪全靠记忆。重开同一文档无法接着上次的位置继续阅读。

## 功能描述

1. **位置记忆**：按文件记录上次阅读的滚动位置，重开自动滚回。
2. **阅读进度标记**：侧边栏文件名旁显示「已读 / 未读 / 阅读中」状态。

## 实现方案

- 使用 `localStorage`，key 形如 `readpos:<file_path>`，value 存 `scrollTop` 与时间戳
- 文件加载渲染完成后（含 MathJax 排版完成），读取并恢复滚动位置
- 滚动时（debounce）写入当前位置
- 阅读进度：根据 `scrollTop / scrollHeight` 计算百分比
  - 0% → 未读（灰）
  - 1–95% → 阅读中（蓝 / 进度条）
  - >95% → 已读（绿 / 对勾）
- 侧边栏 `loadFileList` 渲染时读取进度状态并加标记

## 涉及文件

- `src/static/app.js` — 位置存取、滚动恢复、进度计算、侧边栏标记
- `src/static/app.css` — 进度标记样式（小圆点 / 进度条 / 对勾）
- （可选）`src/translations.py` — tooltip 文案

## 验收标准

- [ ] 打开已读过的文档，自动滚回上次位置
- [ ] 滚动位置在 MathJax/图片渲染完成后才恢复，避免错位
- [ ] 侧边栏文件显示阅读进度状态
- [ ] 进度按文件独立存储，互不干扰
- [ ] localStorage 容量过大时自动清理旧记录

## 资源需求与体验影响分析

### 服务端
- **零负担**：完全基于 `localStorage`，无任何网络请求。

### 客户端（存储 / CPU / 体验）
- **存储（localStorage）**：每条记录约 50–100 字节，无容量风险。但需设上限（如保留最近 200 个文件的位置），并在 `QuotaExceededError` 时淘汰最旧记录——`localStorage` 通常 5–10MB，理论够用，但若与收藏(004)、最近(005)、搜索历史(010) 共用同一域，需统一规划配额，避免单项暴涨挤占其他。
- **CPU**：滚动写入需 debounce（200–500ms），否则高频滚动持续写 localStorage 会卡顿（localStorage 是同步阻塞 API）。
- **体验影响**：**正向**。核心价值是"接着读"，提升连续阅读体验。但有**一个关键时序陷阱**：文档渲染后图片/MathJax 异步加载会改变文档高度，若过早恢复 `scrollTop`，位置会偏移甚至跳到错误位置。**必须在 MathJax `typesetPromise` 完成 + 图片 `onload`（或延迟一帧）之后再恢复滚动**，否则功能反而制造"位置乱跳"的负面体验。
- **滚动恢复抖动**：恢复前可先隐藏内容、定位后再显示，避免可见的跳动闪烁。

## 备注

纯前端，零后端改动；与 issue 001 / 002 都需在「文件渲染完成后」做后续动作，注意编排执行顺序（建议统一一个 `onDocumentRendered(container)` 钩子）。**实现要点：恢复滚动必须晚于 MathJax/图片渲染完成，滚动写入必须 debounce。**

## 背景与痛点

当前点击图片只是简单 `scale(2)` 放大（`setupImageHandlers`），体验粗糙：会溢出容器、无法拖动平移、无法在多图间切换。

## 功能描述

将图片点击放大升级为全屏灯箱，支持缩放、平移、翻图、键盘操作。

## 实现方案

- 新增灯箱浮层（fixed 全屏 + 半透明遮罩）
- 点击文档内图片 → 打开灯箱显示该图
- 功能：
  - 滚轮 / 按钮 缩放
  - 拖拽平移
  - 左右键 / 箭头 在当前文档的所有图片间切换
  - ESC / 点击遮罩 关闭
  - 双击复位缩放
- 替换现有 `setupImageHandlers` 中的 `scale(2)` 逻辑

## 涉及文件

- `src/static/app.js` — 灯箱组件、手势与键盘绑定（替换 `setupImageHandlers` 的 onclick）
- `src/static/app.css` — 灯箱与遮罩样式
- `src/translations.py` — 若有按钮 tooltip

## 验收标准

## 资源需求与体验影响分析

### 服务端
- **零额外负担**：灯箱展示的是已加载的图片（同源 `/api/image`），不产生新请求类型。但注意：当前**每张图片都是独立的 `/api/image` 请求**，文档图多时本就并发多个请求挤占 Werkzeug 线程，灯箱翻图不新增压力，只是复用。

### 客户端（内存 / CPU / 网络 / 体验）
- **内存（重点）**：灯箱若缓存"当前文档所有图片"以支持左右翻，会在内存中持有多个解码后的图像位图，**大图（高分辨率照片）每张可达数十 MB**，多张叠加可能撑爆低端设备内存。缓解：仅保留当前 ±1 张预加载，其余按需加载。
- **网络**：翻图时按需请求，已加载的走浏览器 HTTP 缓存（`/api/image` 已开 `conditional` 缓存）。
- **CPU**：缩放/拖拽用 CSS transform（GPU 合成），避免触发重排；手势监听需 passive + rAF。
- **体验影响**：**显著正向**——当前 `scale(2)` 的简陋放大是公认的"粗糙"体验，灯箱是阅读图文文档的标配。**取舍**：优先纯手写而非引库，避免新增 CDN 依赖（契合 memory `perf-frontend-cdn-bottleneck` 记录的"CDN 是首屏瓶颈"现状——灯箱是交互后才触发的非关键资源，绝不应让它阻塞首屏）。

## 备注

优先纯手写以避免新 CDN 依赖。**内存要点：图片预加载仅当前 ±1 张，勿一次性缓存全文档图片。**

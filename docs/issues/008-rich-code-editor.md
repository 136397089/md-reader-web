## 背景与痛点

当前编辑模式是裸 `<textarea>`，无语法高亮、无行号、无自动配对、无查找替换，编辑体验与阅读体验落差大。

## 功能描述

将编辑器升级为带 Markdown 语法高亮与基础编辑能力的代码编辑器。

## 实现方案

- 引入编辑器内核：CodeMirror 6（轻量、模块化）或 Monaco（功能强但体积大）
- 能力：
  - Markdown 语法高亮
  - 行号、行折叠
  - 自动配对括号 / 引号 / 代码块
  - 查找替换（Ctrl+F）
  - Tab 缩进、列表续行
- 替换 `toggleEditMode` 中对 `textarea` 的依赖
- 注意：`saveFile()` 与 `preview` 读取内容需改为从编辑器实例 `getValue()`

## 涉及文件

- `src/static/app.js` — 编辑器集成、与 save/preview 对接
- `src/static/app.css` — 编辑器主题（对接暗色模式）
- `src/template/main_template.py` — 编辑器容器、资源引入
- 依赖管理 — 新增库（注意 CDN 性能，见 memory `perf-frontend-cdn-bottleneck`，优先本地化打包）

## 资源需求与体验影响分析

> ⚠️ 这是本批需求中**对前端资源/首屏影响最大**的一项，需重点权衡。

### 服务端
- **零额外负担**：编辑器纯前端；保存仍走现有 `/api/save`。

### 客户端（包体积 / 内存 / CPU / 网络 / 首屏）— 重点
- **包体积**：CodeMirror 6 核心约 ~150KB（gzip 后 ~50KB），Monaco 高达数 MB。**这是关键资源冲突点**：项目首屏本就被 MathJax（CDN）阻塞（见 memory `perf-frontend-cdn-bottleneck`），再引大型编辑器会**显著拖慢首屏**。必须：
  - **懒加载**：编辑器仅在用户点"编辑"时动态 `import()`，不进首屏 bundle；
  - **本地化打包**：编辑器资源放本地 `/static`，不走 CDN，避免跨境延迟叠加；
  - 优先 CodeMirror 6 而非 Monaco。
- **内存**：编辑器实例对大文档（>1MB）会占可观内存；多 Tab 各开一个实例会累积，需在关闭 Tab 时销毁实例。
- **CPU**：语法高亮实时解析，超大文档输入时可能掉帧，CodeMirror 6 有内置分块解析缓解。
- **体验影响**：**对编辑场景正向、对整体首屏负向（若处理不当）**。编辑是低频操作（阅读为主），绝不能让它拖累高频的阅读首屏。**懒加载是硬性要求**。

### 取舍结论
若首屏性能优先级最高，编辑器是"可选增强"，且必须懒加载 + 本地化，否则得不偿失。

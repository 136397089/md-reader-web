## 背景与痛点

打开文档时缺少元信息：字数、预计阅读时长、最后修改时间。不利于评估文档规模与新鲜度。

## 功能描述

在文档顶部或侧边展示元信息条：字数、预计阅读时长、最后修改时间。

## 实现方案

- 后端在 `/api/markdown` 返回中补充字段：
  - `word_count`（中文按字符 + 英文按词）
  - `mtime`（文件最后修改时间，`os.path.getmtime`）
- 前端计算预计阅读时长（中文 ~300 字/分，英文 ~200 词/分）
- 元信息条样式轻量，可折叠

## 涉及文件

- `src/routes.py` — `/api/markdown` 增补返回字段
- `src/static/app.js` — 渲染元信息条
- `src/static/app.css` — 元信息条样式
- `src/translations.py` — 「字数」「预计阅读」「最后修改」文案

## 验收标准

- [ ] 显示文档字数（中英文混合统计合理）
- [ ] 显示预计阅读时长
- [ ] 显示最后修改时间
- [ ] 信息条不干扰正文阅读

## 资源需求与体验影响分析

### 服务端
- **极低负担**：`/api/markdown` 已读取全文，附加字数统计与 `os.path.getmtime` 几乎零成本；字数统计在服务端一次性算好返回，避免前端重复扫全文。

### 客户端
- **零额外渲染压力**：仅多一行轻量信息条。
- **体验影响**：**正向**，轻量增强专业感。注意：字数统计对中英文混合需合理（中文按字、英文按词），否则数字不直观反成噪音。

## 备注

轻量增强，可与 issue 003（阅读进度）共用一条「文档信息栏」。**字数统计放服务端一次完成，勿前端重复扫全文。**

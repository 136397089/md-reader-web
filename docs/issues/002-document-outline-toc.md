## 背景与痛点

项目虽已启用 `toc` 扩展，但**大纲没有固定可见**。长文档（如《机器学习概述》）只能靠滚轮定位章节，缺少 Obsidian / Typora 式的可点击大纲导航。

## 功能描述

为当前打开的文档生成可点击的章节大纲面板，支持跳转与当前章节高亮。

## 实现方案

- 渲染后的 `.markdown-content` 中解析所有 `h1`–`h6` 标题
- 为每个标题注入 `id`（若 toc 扩展未自动生成）
- 构建大纲面板（可放右侧或侧边栏内），层级缩进反映标题层级
- 点击大纲项 → 平滑滚动到对应标题
- 滚动监听：根据当前可视区域高亮对应的大纲项（scroll spy）
- 面板可折叠，无标题的文档自动隐藏

## 涉及文件

- `src/static/app.js` — 大纲生成、滚动监听、跳转逻辑（在 `loadMarkdownFile` 渲染完成后触发）
- `src/static/app.css` — 大纲面板样式、缩进、高亮态
- `src/template/main_template.py` — 大纲容器 DOM
- `src/translations.py` — 「大纲」标题文案

## 验收标准

- [x] 打开任意含多级标题的文档，大纲自动生成
- [x] 层级缩进正确（h1 > h2 > h3 ...）
- [x] 点击大纲项平滑滚动到对应章节
- [x] 滚动时当前章节对应的大纲项高亮
- [x] 面板可折叠，无标题文档时隐藏

## 资源需求与体验影响分析

### 服务端
- **零额外负担**：大纲基于已返回的 HTML 在前端解析 `h1–h6`，不发新请求、不增加服务端 CPU/内存。

### 客户端（CPU / 内存 / 渲染 / 体验）
- **CPU**：标题 DOM 遍历 + scroll spy 滚动监听。长文档标题数有限（通常 <100），遍历成本可忽略；但 **scroll spy 的滚动监听若用朴素 `scroll` 事件 + 全量 `getBoundingClientRect()`，高频滚动会触发重排（layout thrash）**，需用 `requestAnimationFrame` 节流或 `IntersectionObserver`。
- **内存**：可忽略。
- **渲染**：大纲面板本身是轻量 DOM，无压力。
- **体验影响**：**正向，且几乎无副作用**。这是阅读长文档（如《机器学习概述》）的关键导航，缺失大纲时用户只能盲滚。属于"低成本高回报"的纯前端增强，唯一注意点是 scroll spy 必须节流，否则在低端设备滚动会卡顿。
- **跨 Tab 影响**：每个打开的 Tab 都会渲染独立文档，scroll spy 监听需绑定到当前激活 Tab 的滚动容器，切 Tab 时正确解绑旧监听，避免泄漏 / 误高亮。

## 备注

纯前端实现，零后端改动；与 issue 001（搜索定位）可共享「滚动到锚点」的工具函数。**注意 scroll spy 用 `IntersectionObserver` 或 rAF 节流，勿用裸 scroll 事件。**
